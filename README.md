# WeatherFit — 오늘의 코디

🇰🇷 한국어 · 🇬🇧 [English](README.en.md)

오늘 날씨에 맞는 남성 코디를 추천하는 웹앱. **올드머니 · 캐주얼 · 포멀 · 미니멀** 네 가지 스타일로,
차분한 쿨톤 위주에 웜톤도 함께 제안합니다.

**▶ https://moriochoradio.github.io/weather-fit/**

아이폰 Safari에서 열고 **공유 → 홈 화면에 추가**하면 앱처럼 쓸 수 있습니다.
서버도 API 키도 필요 없는 정적 웹앱이라, `main`에 푸시하면 GitHub Actions가 테스트 후 자동 배포합니다.

---

## 무엇을 해 주나

### 오늘 뭘 입을지
- 날씨를 종합한 **코디 추천** — 기온대 6단계 × 스타일 4종, 조합마다 2벌 이상 (총 75벌 내장)
- 아침에 보든 저녁에 보든 **앞으로 남은 시간 기준**으로 추천 (밤에 한낮 최고기온 기준 옷을 권하지 않음)
- **다른 코디 보기** — 같은 날 안에서도 순서를 다시 섞어 선택지를 넓힘
- **대안 코디** — "더 시원하게 / 쌀쌀하게 느껴진다면" 인접 기온대 제안
- 비·눈·폭염·한파·일교차·강풍 **대응 조언**과 우천에 취약한 소재 경고

### 어떤 옷인지 한눈에
- 아이템의 **실제 색을 옷 모양에 칠한 미니 실루엣** — 입어보기 전에 색 조합이 와닿게
- 아이템마다 **라인 아이콘** — 코트·패딩·가디건·셔켓·수트·반팔·반바지·부츠·샌들 등 25종 구분
- **쉽게 풀이** — 발마칸 코트, 시어서커 같은 용어를 일반인 눈높이로 설명 + **대체제** 안내 (75개 용어)

### 날씨
- 현재 위치 또는 **전국 시·군 선택**(17개 시·도, 161개 지역 내장 — 지오코딩 API 없이 동작)
- 기온·체감·최저/최고·강수확률·바람 + **미세먼지·자외선지수**, 위험 수준이면 마스크·자외선 조언
- **일일 브리핑** — "아침 24° → 낮 31° → 저녁 27°" + 기온 스파크라인 + "오후 2시~6시 비 — 우산 챙기세요"
- **어제와 비교** — "어제보다 6° 낮아요, 한 겹 더 챙기세요"
- **내일 미리보기**와 **이번 주 예보**(6일치 최고/최저·기온대·비 소식)

### 내 것으로 만들기
- **즐겨찾는 지역** 여러 곳 저장 — 시·군보다 세밀한 지점(역·동 등)도 등록 가능
- **즐겨찾는 코디** 저장 — 필터와 무관하게 언제든 다시 보기
- **입은 기록** — "오늘 이거 입었어요"를 눌러 두면 최근에 입은 코디는 다음 추천에서 뒤로
- **가진 옷 체크** — "이건 없어요"를 눌러 두면 다음부터 대체제를 앞세워 표시
- 마지막으로 고른 **스타일·톤 필터를 기억**

### 그 밖에
- **이미지로 공유** — 실루엣·아이템·팁·색 팔레트를 담은 PNG 한 장 (미지원 환경은 텍스트 → 클립보드로 폴백)
- **오프라인 지원** — 마지막으로 본 날씨·코디를 캐시, 오프라인 상태도 안내
- iPhone Safari · PC 반응형, 다크모드 자동 대응, 홈 화면 추가 시 전용 앱 아이콘

```bash

```

## 기술 스택

Vite + React 18 + TypeScript · 순수 CSS · Vitest · [Open-Meteo](https://open-meteo.com)

**의존성을 일부러 최소로 유지합니다.** 런타임 의존성은 React/ReactDOM 둘뿐이고, 서버·DB·API 키가
없어야 정적 호스팅만으로 굴러가기 때문입니다. 그래서 상태 관리 라이브러리, CSS 프레임워크,
차트 라이브러리, 아이콘 패키지를 쓰지 않고 직접 만들었습니다.

- 코디 실루엣과 아이템 아이콘의 옷 모양: 전부 직접 작도한 SVG (외부 에셋·라이선스 의무 없음)
- 기온 스파크라인, 공유 이미지(PNG) 생성, 서비스워커: 라이브러리 없이 구현

## 왜 이렇게 만들었나 — 기술 선택 Q&A

**Q. 왜 서버·API 키 없이 만들었나?**
A. 날씨는 [Open-Meteo](https://open-meteo.com)가 키 없이 브라우저에서 직접 호출을 허용하고, 지역 검색은 지오코딩 API 대신 전국 161개 지역 좌표를 내장해 해결했습니다. 그 결과 GitHub Pages 정적 호스팅만으로 운영비 0원에 굴러가고, 키 유출·서버 장애·요금 걱정이 원천적으로 없습니다.

**Q. 왜 PWA인가?**
A. "아침마다 잠깐 보는" 도구라 홈 화면 아이콘 한 번 탭으로 열리는 경험이 핵심인데, 앱스토어 배포 없이 이를 얻는 방법이 PWA입니다. `manifest.json`과 서비스워커(`sw.js`)를 직접 작성해 오프라인에서도 마지막 날씨·코디를 보여줍니다.

**Q. 왜 TypeScript인가?**
A. 추천 엔진이 기온대 6단계 × 스타일 4종 같은 조합 규칙 덩어리라, `TempBand`·`StyleId` 유니온 타입으로 잘못된 조합을 컴파일 타임에 차단할 수 있습니다. 코디 75벌·용어 75개 같은 내장 데이터도 전부 타입 검사를 통과해야 빌드가 됩니다.

**Q. 날씨 데이터는 어떻게 얻고, 왜 그 방식인가?**
A. Open-Meteo 예보 API를 브라우저에서 직접 호출합니다. 키 없이 CORS를 허용하는 무료 API 중 시간별 기온·체감·강수확률·자외선까지 주는 곳이라 선택했고, 미세먼지도 같은 서비스의 Air Quality API를 써서 연동을 하나로 유지했습니다.

**Q. 코디 75벌 데이터는 왜 직접 구축했나?**
A. 기온대 6단계 × 스타일 4종 조합마다 2벌 이상을 보장하려면 데이터 구조부터 직접 설계해야 했고, 외부 패션 API나 이미지 저작권에 기대지 않기 위해 실루엣 SVG까지 직접 작도했습니다. 덕분에 저장소 하나에 코드·데이터·에셋이 전부 들어 있고 MIT로 배포할 수 있습니다.

**Q. 왜 추천 로직을 `engine/` 순수 함수로 분리했나?**
A. 추천 룰·브리핑 문구·실루엣 배치는 DOM 없이 입력→출력만 검증하면 되는 로직이라 순수 함수로 분리했습니다. 그래서 283개 단위 테스트가 브라우저 없이 빠르게 돌고, 화면과 공유 이미지가 같은 배치 계산을 재사용합니다.

## 구조

```
src/
├── engine/          순수 함수 — 테스트가 집중되는 곳
│   ├── recommend.ts     추천 룰 (기온대 판정·톤 필터·강수 정렬·날씨 조언)
│   ├── briefing.ts      하루 흐름 브리핑, 어제/내일 비교 문구
│   ├── silhouette.ts    실루엣 배치 계산 (화면·공유 이미지가 공유)
│   └── weatherCodes.ts  WMO 기상 코드 분류
├── data/            내장 데이터
│   ├── outfits.ts       코디 75벌
│   ├── regions.ts       전국 시·군 161곳
│   ├── glossary.ts      패션 용어 75개 + 대체제
│   ├── colors.ts        색 이름 → hex
│   └── clothingPaths.ts 의류 실루엣 SVG path
├── services/        외부 연동 · 브라우저 저장소
│   ├── weather.ts       Open-Meteo 예보
│   ├── airQuality.ts    미세먼지
│   ├── geo.ts           위치 권한 · 지역 저장 · 즐겨찾기
│   ├── shareImage.ts    코디 카드 → PNG
│   └── prefs · savedOutfits · wornLog · wardrobe
└── components/      화면
```
