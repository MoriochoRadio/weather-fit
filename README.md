# Weather Fit

**오늘 날씨를 "무엇을 입을지" 하나의 결정으로 번역하는 남성 코디 가이드.**
서버도 API 키도 없이, 브라우저만으로 도는 정적 PWA입니다.

### 👉 **[바로 사용하기 — moriochoradio.github.io/weather-fit](https://moriochoradio.github.io/weather-fit/)**

---

## ❓ 왜 만들었나

아침마다 같은 고민을 반복했다. **기온 숫자는 아는데 그게 무슨 옷인지 모르겠다.** 15도는 얇은 니트인지 얇은 재킷인지, 오늘 비가 온다는데 신발을 바꿔야 하는지.

날씨 앱은 숫자와 아이콘까지만 알려주고 거기서 끝난다. 코디 앱은 옷장을 등록하고 사진을 찍어야 시작된다. **그 사이가 비어 있었다** — "오늘 날씨면 이 정도 두께"를 알려주는 것.

그래서 목표를 좁게 잡았다.

- **등록 없이 즉시** — 앱을 열면 바로 오늘의 한 벌이 나온다
- **글자만으로 부족하다** — "차콜 울 슬랙스"라고 써도 감이 안 온다. 실제 색을 칠한 옷 모양을 함께 보여준다
- **서버 없이** — 개인용이라 운영비가 들면 안 된다. 날씨는 브라우저에서 직접 호출하고, 기록은 이 기기에만 남긴다

## 무엇을 하는 앱인가

| 영역 | 내용 |
|---|---|
| **코디 추천** | 4개 스타일(올드머니·캐주얼·포멀·미니멀) × 6단계 기온대에 맞춘 **코디 75벌**. 상의·하의·신발·아우터·포인트와 착장 팁, "조용한 포인트" 한 줄 |
| **옷 실루엣** | 코디 문구에 맞는 옷 모양에 **실제 색을 칠한 SVG 실루엣** + 팔레트. 글자만으로는 감이 오지 않는 문제에 대한 답 |
| **지역** | 전국 **161곳** (10개 권역). 지역명·권역명 검색, 즐겨찾는 지역 빠른 전환 |
| **날씨** | 체감·강수·바람·습도·UV, 시간별 기온·강수 그래프, 내일 미리보기, 주간 예보 |
| **상황 반영** | 체감 보정(추위/더위 탐), 일정별(출근·주말·저녁) 조정, 강수 확률 50% 이상이면 신발·소품 자동 보정 |
| **출발 시각** | 비가 오기 시작하는 시간을 읽어 지금 나갈지 알려줌 |
| **옷장 연동** | 없는 아이템을 표시하면 같은 온도 균형을 유지하는 대체 아이템 제안 |
| **주간 준비** | 앞으로 5일을 보고 방수 신발·차양 아이템·여벌 이너를 미리 꺼내둘 것으로 정리 |
| **기록** | 저장한 룩·착용 기록, JSON 파일로 내보내기·불러오기, 기기 기록 초기화 |
| **PWA** | 홈 화면 설치, 오프라인 캐시 |

## 데이터와 프라이버시

- 날씨는 [Open-Meteo](https://open-meteo.com/)를 브라우저에서 직접 호출합니다. **API 키가 필요 없고 서버를 거치지 않습니다.**
- 선택한 지역·스타일·저장한 룩·착용 기록은 **브라우저 `localStorage`에만** 저장됩니다. 서버로 전송되는 데이터가 없습니다.
- 기기를 옮길 때는 **내 기록 내려받기**로 JSON을 받아 다른 브라우저에서 불러오면 됩니다.

## 추천이 정해지는 방식

체감 기온을 6단계 기온대로 나눈 뒤, 해당 스타일·기온대·톤에 맞는 코디를 날짜 시드로 섞어 고릅니다.

| 기온대 | 한파 | 추움 | 쌀쌀 | 선선 | 따뜻 | 더움 |
|---|---|---|---|---|---|---|
| 체감 | 0° 미만 | 0–9° | 9–17° | 17–23° | 23–28° | 28° 이상 |

- **같은 날·같은 조건이면 같은 결과**가 나오고, 날짜가 바뀌면 후보 안에서 자연스럽게 돌아갑니다.
- 비 예보에는 비에 강한 코디를 앞세우고, 그래도 맞지 않으면 신발과 소품만 교체해 실루엣은 지킵니다.
- 톤 필터가 좁아 후보가 없으면 톤을, 그래도 없으면 가장 가까운 기온대로 넓혀 **빈손으로 남지 않게** 합니다.
- 날씨 API가 이상값(NaN·Infinity)을 주면 가장 더운 극단이 아니라 중간값(선선)으로 폴백합니다. 한겨울에 반팔을 추천하는 사고를 막기 위한 장치입니다.

## 기술 구성

정적 HTML·CSS·JavaScript만 배포하며 API 서버, 데이터베이스, 인증 런타임을 포함하지 않습니다. 런타임 의존성은 8개입니다.

| 의존성 | 사용처 |
|---|---|
| `react`, `react-dom` | 렌더링과 로컬 상태 |
| `wouter` | 라우팅 |
| `lucide-react` | 아이콘 |
| `@radix-ui/react-slot`, `class-variance-authority` | 버튼 변형 |
| `clsx`, `tailwind-merge` | 클래스 병합 |

번들은 앱 코드 102 kB(gzip 31 kB) + 벤더 240 kB(gzip 75 kB) + CSS 47 kB(gzip 11 kB)입니다.

## 배포

`main`에 푸시하면 [`.github/workflows/deploy-pages.yml`](./.github/workflows/deploy-pages.yml)이 타입 검사 → 테스트 → 빌드를 거쳐 GitHub Pages로 배포합니다. 운영비는 들지 않습니다.

Pages 경로(`/weather-fit/`)는 빌드 시 `GITHUB_PAGES=true`로 결정되고, 코드는 `import.meta.env.BASE_URL`만 참조하므로 저장소 이름을 바꿔도 따라갑니다.

## 🧪 한계

- **옷장을 모른다.** 추천한 옷을 실제로 갖고 있는지는 사용자가 "없음"으로 표시해야 안다. 옷장 등록을 없앤 대가다.
- **코디 75벌은 고정된 큐레이션이다.** 개인 취향 학습이나 추천 개선이 없다. 같은 조건이면 같은 날 같은 결과가 나온다(의도한 동작이지만, 취향이 다르면 맞지 않을 수 있다).
- **날씨 출처가 하나다.** Open-Meteo가 죽으면 앱도 멈춘다. 키가 필요 없는 대신 대체 경로가 없다.
- **실루엣은 근사치다.** 옷 모양을 문구에서 유추해 그린다. "차콜 캐시미어 블렌드 코트"의 재질감까지는 표현하지 못한다.

## ✍️ 회고

**AI 에이전트에게 개선을 통째로 맡겼다가 되돌린 기록이 이 저장소의 가장 값진 부분이다.**

2026-07-27에 시작해 열흘 만에 v1.9까지 만들었다. 코디 75벌, 지역 161곳, 색을 칠한 옷 실루엣, 패션 용어 77개, 회귀 테스트. 그리고 08-13에 **"더 좋게 만들어 달라"고 Manus에게 맡겼다.**

돌아온 것은 **전면 재작성본**이었다. 화면은 확실히 세련돼졌고 없던 기능도 생겼다 — 상황별(출근·주말·저녁) 코디, 출발 시각 제안, 시간별 기온·강수 그래프, 즐겨찾는 지역, 주간 옷장 준비, 기록 내보내기, PWA 설치. 그런데 데이터가 사라져 있었다.

| | 재작성 전 | 재작성 후 |
|---|---|---|
| 코디 | 75벌 | **12벌** |
| 지역 | 161곳 | **5곳** |
| 옷 실루엣 | 있음 | **없음** |
| 패션 용어 | 77개 | **없음** |
| 테스트 | 있음 | **0개** |

**기능은 늘었는데 알맹이가 빠진 것이다.** 게다가 그 상태가 3주 가까이 라이브로 나가 있었다.

08-18에 정리했다. **새 UI와 신기능은 그대로 두고, 사라진 데이터만 되살렸다.** 되살리는 과정에서 기온대를 3단계에서 6단계로 되돌리고, 날짜 시드 기반 결정적 추천도 복원했다. 지금의 75벌·161곳·실루엣·용어·테스트 79개가 그 결과다.

정리하면서 **공개 배포에 섞여 있던 것들도 발견했다** — 세션 리플레이·콘솔·네트워크를 수집하는 26KB 디버그 스크립트가 라이브에 그대로 올라가 있었고, 환경변수가 치환되지 않은 분석 태그가 접속할 때마다 404를 만들고 있었다. 런타임 의존성도 51개에서 8개로 줄였다. 앱이 실제로 쓰는 건 8개뿐이었다.

**배운 것은 두 가지다.**

첫째, **AI 에이전트에게 "개선"을 맡기면 개선의 정의가 다를 수 있다.** 에이전트는 화면과 기능을 늘렸고 그것도 개선이 맞다. 하지만 데이터가 6분의 1로 줄어든 것은 알려주지 않았다. **무엇을 지켜야 하는지 먼저 말했어야 했다.**

둘째, **커밋 메시지를 믿으면 안 된다.** 재작성 커밋들은 전부 정상적인 개선처럼 적혀 있었다. 숫자를 직접 세어 보기 전까지는 몰랐다.

재작성 직전 상태는 `backup/pre-managed-sync-20260813` 브랜치에 그대로 남겨 두었다.
